ESP32-P4 + 3× SN65HVD230 三路 CAN 的特斯拉 Model 3/Y/YL 车总线固件 · 面向 2024 款 Model Y
ESP32-P4 / Arduino-ESP32 3.3.12 3 × TWAI 原生控制器 5 个车型 profile 非公开道路用途

1它是什么：T2CAN 版的“三总线”重写

同一作者的 T2CAN-Universal 只用板载两路 CAN，所以必须二选一：要么接 Body + Chassis（有 Advanced EAP，没扭矩法 NAG），要么接 Party + Chassis（有 NAG，丢 Advanced EAP）。 这个 P4 版把 MCU 换成 ESP32-P4，而 P4 片上就有 3 个 TWAI 控制器，于是三路 CAN 可以同时在线，不再有二选一。

维度T2CAN 版P4-CAN 版（本仓库）
MCUESP32-S3（2 路 CAN：MCP2515 + TWAI）ESP32-P4（3 路原生 TWAI）
同时在线总线2 路，拓扑二选一3 路：BODY + CHASSIS + PARTY
NAG killer取决于拓扑扭矩法与 TSL9 都可选
供电12–24V 直供、光耦隔离USB-C 5V（需另配车载降压）
成本板 ~$24（成品工业板）板 ~$14–25 + 3 个收发器模块
成熟度较成熟BETA，BLE 部分作者自注 “need some fix”
仓库标题直接写着 BETA。VALIDATION.md 明确记录：未在真机烧录、未做 CAN 实测、未做整车/道路测试。 作者自己的验证只到“主机测试 + 编译通过”。把它当“可以开始验证的固件”，不要当成已验收产品。

层实现

CAN 驱动ESP-IDF 原生 driver/twai.h 的 _v2 API，三个独立 handle，500 kbit/s，accept-all 滤波
Web / UIArduino WebServer + 内嵌 gzip HTML：dashboard_source.html → tools/build_dashboard.py → index_html.h

BLENimBLE，绑定 + Secure Connections；内置 TinyCrypt ECC 修复（Espressif commit 9fd7cb7），解决 DHKey Check Failed (0x50b)

测试主机侧 C++（g++/clang + ASan/UBSan）、Python unittest、Node 仪表盘 DOM 测试 —— 不依赖硬件

3项目结构：按“纯逻辑 / 运行时 / 适配层”三层切分

没有 src/main.cpp 那种常规布局，而是扁平的单 sketch。所有 .h 与 .ino 必须放在同一目录，目录名必须等于 .ino 文件名。

设计上值得学的一点：*_pure.h 与 *_runtime.h 成对出现 —— 纯逻辑不带 Arduino.h， 所以 2000+ 行的 NAG/R79/TSL9 策略可以在 Mac 上用 g++ 直接跑回归，不必上板。这也是它能在没有硬件的情况下声称“验证过”的唯一依据。

4整体目标与功能清单

目标一句话：在不改写车机软件的前提下，通过总线注入把被区域/法规限制的智驾能力放开。三路总线各自承担不同职责：

功能主要总线做什么状态
NAG killerPARTY（扭矩法）/ CHASSIS（TSL9）抑制“请握方向盘”提示核心功能
Advanced EAPBODYNOA 请求变道时自动打转向灯，可配延迟、可取消核心功能
EU Unlock / R79BODY（0x3FD）放开 ECE R79 限制、Summon 扩到 ±85 m、横向加速度上限核心功能
TLSSC 激活BODY区域未开放时强行点亮交通灯/停车标志控制核心功能
Continuous APBODY + CHASSISAP 被接管后自动重连实验性
ISA 提示音抑制—关掉限速提示音可用
Country / Map 区域伪装—改国家/地图区域标识可用，合规风险最高的一项
Vision 限速 / 踏板映射—视觉限速与油门响应微调可用
S3XY ButtonBLE蓝牙按键直连（最多 3 只）作者自注 need some fix
CAN 抓包 / LAB全部Snapshot / RAW 导出，只读不回放研究用
README 开头写明“部分功能需要有效的 EAP/FSD 订阅”。这不是破解订阅，而是改车辆本地策略位； 订阅状态、账号区域、车辆固件版本都可能让某一项失效，且 Tesla 的 OTA 随时可能改掉帧定义。

5硬件：和 T2CAN 版的三个关键差异

项说明
板子Waveshare ESP32-P4-WIFI6（建议买 -M 版：排针已焊好；标准版排针需自焊）。SKU 32020 / 31647。板载 C6 已带 PCB 天线，不需要外接天线
收发器3 个 SN65HVD230 模块（3.3V 逻辑，与 P4 电平匹配）。别用 TJA1050 / 5V 模块，会反灌 P4 的 IO
供电最大差异：P4 板走 USB-C 5V，不像 T2CAN 能直吃 12V。必须配 12V→5V/3A 车载降压（点烟器车充或裸降压模块）+ 保险丝
接线量T2CAN 只需引 2 对 CAN；这里要引 3 对（Party / Body / Chassis）+ 12V + GND，1 分 3 线束从“可选”变成“必需”
终端电阻3 个模块各有一颗 120 Ω，上车前三个都要拆（车上总线两端已有终端）；台架阶段每个总线留一颗
高速模式SN65HVD230 的 Rs 脚决定斜率控制/高速，README 要求把模块切到 high-speed（Rs 接地）

引脚映射（默认板型）

物理总线TWAIP4 TXP4 RX车上取点（X179）
CAN 1 · BODYTWAI 0GPIO20GPIO21BODY 对（13/14 或 9/10，按实测）
CAN 2 · CHASSISTWAI 1GPIO22GPIO23CHASSIS 对（18/19）
CAN 3 · PARTYTWAI 2GPIO26GPIO27PARTY 对（2/3）

若用作者的 “ESP32P4 WIFI6 3CAN” 扩展板，编译时加 -DP4CAN_BOARD_X179，引脚改为 2/3、4/5、26/27（pin_config.h 里已写好映射，并注明板丝印的 CAN1/CAN2 与 X179 是反的）。

7编译与烧录

第一步：目录改名（否则 Arduino 根本认不出 sketch）

git clone https://github.com/06066060606060/P4can-universal-unlock.git
mv P4can-universal-unlock P4-CAN-Universal-v3.29.3
# 目录名必须 == .ino 文件名（去掉扩展名），这是 Arduino 的硬规则

第二步：编译

FQBN="esp32:esp32:esp32p4:ChipVariant=postv3,FlashSize=32M,PartitionScheme=app5M_fat24M_32MB,PSRAM=enabled,USBMode=hwcdc,CDCOnBoot=cdc,FlashMode=qio"

arduino-cli compile --fqbn "$FQBN" --warnings default P4-CAN-Universal-v3.29.3

第三步：烧录

arduino-cli board list          # 找串口，通常是 /dev/cu.usbserial-* 或 /dev/cu.wchusbserial*
arduino-cli upload -p /dev/cu.usbserial-XXXX --fqbn "$FQBN" P4-CAN-Universal-v3.29.3
坑 1：官方的 python 构建脚本跑不了。tools/build_p4.py 会去仓库外部找 ../tools/build_ota.py （属于作者的私有工作区，没随仓库发布），找不到就直接 SystemExit。别在这条路上耗时间，直接用上面的 arduino-cli 命令。
坑 2：tinycrypt 头文件路径。src/p4_tinycrypt/*.c 里写的是 #include <tinycrypt/ecc.h>， 而头文件在 third_party/tinycrypt/include/tinycrypt/，build_opt.h 里没有对应的 -I。 若编译报 fatal error: tinycrypt/ecc.h: No such file or directory，二选一修：
① 把 third_party/tinycrypt/include/tinycrypt/ 整个复制到 src/tinycrypt/；
② 或加编译参数 --build-property "compiler.c.extra_flags=-I$PWD/third_party/tinycrypt/include"（cpp 同理再加一条）。
坑 3：串口日志看哪个口。这块板的 Type-C 后面是 CH343P USB-UART；而固件要求 USB Mode = Hardware CDC and JTAG + CDC on boot，说明 Serial 走的是 P4 原生 USB（板上 4-pin MX1.25 口）。 所以：烧录走 Type-C 没问题，但要看启动日志/走 USB 抓包协议，得接那个 4-pin 转 USB 线（KIT-A/B 附带）。

8首次开机配置

  1. 上电，连热点SSID 为 P4-CAN-XXXX（取 MAC 末两字节），默认密码 12345678，仪表盘 http://192.168.4.1。
  2. 选车型 profile2024 款 Model Y → Model Y Legacy；拓扑 Triple Standard（A=BODY、B=CHASSIS、extra=PARTY）。
  3. 理解 fail-closed没有有效 profile 时，固件只启 Wi-Fi/Web：不发一帧 CAN、不开 BLE、不启注入。所以“灯亮但车没反应”先回去看 profile 有没有存上。
  4. 看三路是否真在收Diagnostics / Recovery 页会给每路独立显示 init error、RX 调用数、队列、TEC/REC。三路都必须有 RX 才算接线对。
  5. 再开功能Settings 里逐项开（Advanced EAP → NAG → EU Unlock → TLSSC），每开一项跑一次验证，别一次全开。
比 T2CAN 版省事的地方：因为三路同时在线，vehicleProfileNagTorqueSupported() 对所有有效拓扑都返回 true —— 不再需要为了 NAG 去牺牲 Advanced EAP。

10排错顺序

现象先查什么
编译报 requires ESP32-P4 with three TWAI controllersFQBN 里 ChipVariant 漏了，或选了别的芯片
编译报 ARDUINO_USB_MODE / CDC_ON_BOOT 断言FQBN 必须含 USBMode=hwcdc,CDCOnBoot=cdc
烧录成功但热点搜不到C6 的 Hosted 固件版本不匹配；看 Type-C 串口有没有 HOSTED_PINS_FAILED
三路里某一路 RX 恒为 0该对针脚接错总线 / 收发器 CANH-CANL 反了 / 模块 Rs 没切高速
一路反复 bus-off该模块的 120 Ω 没拆
能连 Wi-Fi 但页面空白index_html.h 与 dashboard_source.html 不同步；跑 tools/build_dashboard.py 重新生成
BLE 配对失败 e=1291正是 v3.29.3 修的那个 TinyCrypt ECC 缺陷；确认 src/p4_tinycrypt 真的被编译进去了

11边界与风险

  • 没有整车验证。作者明确记录未烧录、未接 CAN、未路测。三路总线同时注入的时序风险，只能由你在台架上自己论证。
  • OTA 会让它失效。Tesla 改帧定义或加校验是常态，这类项目历史上都是“能用一段时间，然后某次 OTA 就废了”。
  • 合规。改国家/地图区域的 Country Override、绕过 ECE R79 的限制，在多数地区属于非法改装；国内可能被认定擅自改变车辆技术参数，并影响质保与理赔。
  • 安全。NAG killer 抑制的是驾驶员注意力监控，配合脱手使用会显著提高事故概率。仓库自己写明“仅限受控台架与研究环境”。
  • 供电。P4 板经 USB-C 5V 供电，车载降压模块的纹波与浪涌比 T2CAN 的隔离 12V 输入脆弱得多，建议加 TVS + 保险丝，并在熄火后断电路径上做验证，避免静态亏电。
